# تقرير تسليم — مشروع Azizos

## فكرة المشروع والهدف
Azizos تطبيق واحد (exe واحد موقّع لاحقاً) يحل محل "AME Wizard" اللي يستخدمه صاحب البلاي بوك (AZIZ) لتوزيع تحسينات ويندوز مجانية لمستخدميه. التطبيق:
- يقرأ النظام (نسخة ويندوز، كرت الشاشة، نوع القرص، لابتوب/مكتبي) ويطابق التويكات معه تلقائياً.
- يفحص متطلّبات مسبقة (Defender، مضاد فيروسات آخر، الشاحن) قبل التطبيق.
- يعرض كل تويك بشفافية (اسمه، وصفه، كم إجراء، أي نوع) ويخلي المستخدم يختار.
- يطبّق بمتانة: خطأ بتويك واحد ما يوقف الباقي، وكل خطأ له رمزه الحقيقي.
- يحفظ القيم الأصلية قبل أي تعديل (تقرير على سطح المكتب).
- يفتح "AZIZ Gaming Optimizer" تلقائياً بعد إعادة التشغيل.
- عربي/إنجليزي (RTL للعربي)، تصميم خاص بهوية AZIZ (مو شكل AI افتراضي).

## طلبات المستخدم الأساسية (بالترتيب التاريخي)
1. بناء Azizos من الصفر: محرّك Rust + واجهة Tauri، متوافق مع ويندوز 10/11 كل الإصدارات (بيلدات 19044–26300)، بدون إنترنت وقت التشغيل.
2. الشفافية والأمان: ما نكتب كود تجاوز حماية جديد — فقط نشغّل سكربتات صاحب البلاي بوك الموجودة أصلاً، وبعد موافقة صريحة من المستخدم. كشف الحالة قراءة فقط.
3. **التحقق الفعلي** من ادّعاءات معيّنة (بدون نافذة سوداء، System32 مباشر، GPU عبر API، عزل الأخطاء، حفظ القيم الأصلية، فروقات طُبّق/مطبّق مسبقاً/غير منطبق/خطأ حقيقي فقط).
4. إعادة تصميم الواجهة بأسلوب يشبه AME لكن بهوية AZIZ خاصة وفريدة.
5. استخدام **أخف طبقة ممكنة** لكل نوع إجراء (ريجستري، خدمات، appx، الطاقة، الأجهزة، bcdedit) — يعني Windows API مباشر بدل تشغيل أدوات/PowerShell كل ما أمكن.
6. جسر قوي وخفيف بين Rust والتويكات (JSON مدمج داخل الـ exe وقت البناء).
7. توثيق ممتاز وكود صعب التسريب.
8. خطة تطوير + اقتراحات، وجواب: Rust أو C++ أو C#؟ (الجواب: نبقى Rust).
9. تحدّث لاحق: المستودع **يبقى عام** (المستخدم مب معروف، ما يهمه الكشف)، المهم الكود ما "يتسرب" بمعنى الانتحال — يعني التوقيع الرقمي لاحقاً هو الحل، مو إخفاء الكود.
10. المثبّتات الناقصة (vcpp, OpenShell, 7-Zip) تنحمّل وتندمج داخل الـ exe نفسه — المستخدم النهائي ما يحمّل ولا يثبّت شي منفصل.
11. تطوير إضافي: نقل powerplan/scheduled_task/appx/device من أدوات خارجية (PowerShell/powercfg/schtasks) إلى Windows API مباشر (powrprof، ITaskService، WinRT PackageManager، SetupAPI).
12. التأكد الفعلي بالبناء والاختبار الحقيقي على جهاز Windows (مو فحص أنواع بس) — وهذا صار بعد ما تبيّن إن Visual Studio + Windows SDK + MSVC موجودين على الجهاز أصلاً.

## أسلوب التواصل المطلوب (مهم)
- **عربي دائماً** في هذه الجلسة (تعليمات صريحة من المستخدم) — كل رد لازم يكون عربي.
- ينفّذ مباشرة بدون سؤال كل خطوة، إلا إذا القرار فعلاً يحتاج موافقة المستخدم (تنزيل ملفات، تغييرات لها أثر خارجي).
- يحب التحقق الحقيقي لا الافتراضات — لمّا يسأل "هل تأكدت؟" يقصد دليل فعلي (اختبار شغّال، بناء ناجح)، مو كلام نظري.
- يفضّل الحلول المدمجة اللي ما تحتاج خطوات إضافية من المستخدم النهائي (كل شي داخل exe واحد).
- صريح بخصوصياته: المستودع عام وما يمانع، بس يهتم بعدم "تسريب"/انتحال الكود لاحقاً.

## وش صار (محقَّق فعلياً، مو افتراض)
- **المحرّك (Rust)**: schema/catalog/exec/detect مكتملة، 33 اختبار **حقيقي** ناجح على هذا الجهاز (يلمس الريجستري، SCM، IOCTL القرص، كرت الشاشة، WinRT appx فعلياً — مو type-check بس).
- **التوولتشين**: تحوّل من GNU إلى MSVC (كان موجود Visual Studio أصلاً، بس Rust كان على توولتشين خطأ).
- **بناء حقيقي ناجح**: `azizos-app.exe` (~48MB) و`Azizos_0.0.5_x64-setup.exe` (مثبّت NSIS حقيقي، ~42MB) — بُنيا فعلياً على الجهاز، مافيه أي خطأ.
- **حالات صادقة**: Applied/AlreadyApplied/NotApplicable/Failed/Skipped — في المحرّك والتقرير والواجهة؛ فقط الأخطاء الحقيقية (برمزها) تظهر كخطأ.
- **أخف الطبقات** لأربعة أنواع إجراءات صارت Windows API مباشر بدل أدوات خارجية:
  - الخدمات → SCM API مباشر
  - appx (٧٠ إجراء) → **WinRT PackageManager** (صفر PowerShell بدل ما يصل لـ٧٠ عملية)
  - الطاقة (powerplan) → **powrprof.dll** مباشر
  - الأجهزة (device) → **SetupAPI** مباشر (نفس طريقة Device Manager)
  - الريجستري، إنهاء العمليات، كشف SSD/HDD، كشف الكرت: كلها API مباشر من البداية
- **إصلاح خلل حقيقي**: build.rs كان يدمج **كل** مجلد assets داخل الـ exe (٦٢ ميقا فيها ملفات .sys ومثبّت قديم ما يستخدمهم أي تويك) — صار يدمج فقط الملفات اللي تويك يفتحها فعلياً بالاسم.
- **المثبّتات الثلاثة** (vcpp، OpenShell، 7-Zip) انحمّلت من مصادرها الرسمية واندمجت داخل الـ exe — ما تبقى ملفات ناقصة. سكربت `fetch-vendor-assets.ps1` يعيد تنزيلها بنفس الطريقة أي وقت.
- **الواجهة**: صُممت من جديد بأسلوب يشبه AME (لوحة البلاي بوك، بطاقات المتطلّبات، صفحات خيارات مقسّمة، عدّاد تطبيق دائري) بهوية AZIZ (الزوايا المقصوصة، الذهبي، الخط). جُرّبت بالعربي والإنجليزي في المتصفح.
- **الكتالوج**: 25 تويك / 883 إجراء محوّلة من البلاي بوك، بأسماء ووصف عربي/إنجليزي حقيقي (مو "Core — registry" فقط).
- **التوثيق**: ENGINE.md وDETECTION.md أعيد كتابتهم ليطابقوا الكود الفعلي، وROADMAP.md فيه خطة التطوير والمقارنة مع C++/C#.
- **الكود مدفوع لـGitHub** (مستودع عام z3tbz/Azizos)، آخر كوميت `b51a59e`.

## وش ما صار بعد
- **المهام المجدولة (scheduled_task) عبر COM** (ITaskService): مؤجّلة لأنه ولا تويك من الـ25 يستخدم هذا النوع حالياً — أثرها صفري الآن، فأعطينا الوقت للي له أثر فعلي.
- **الشبكة** (netsh/سكربتات → ريجستري + IP Helper API): لم يُبدأ.
- **NVIDIA** (مفاتيح الدرايفر + NVAPI DRS للبروفايل): لم يُبدأ.
- **fsutil/label/DISM** عبر API مباشر بدل الأوامر: لم يُبدأ.
- **التجربة على VM حقيقية** لكل نسخة ويندوز (10/11، Home/Pro/LTSC/IoT): لم تصر — فقط اختُبر على جهاز المطوّر الحالي.
- **التوقيع الرقمي**: لم يصر — هذا أهم خطوة قبل أي نشر عام (يحل مشكلة "تسريب/انتحال" اللي يهتم فيها المستخدم).
- **ميزات المرحلة 3** (زر استرجاع من report.json، معاينة Dry-run بالواجهة، نقطة استعادة ويندوز، تجميع متوازي): لم تُبدأ.

## الخطة المختصرة (الخطوة الجاية)
1. توقيع رقمي للـ exe (Authenticode) — يحل قلق "التسريب/الانتحال" بشكل عملي.

3. إكمال الطبقات الخفيفة الباقية (الشبكة، NVIDIA، fsutil/DISM، ITaskService لو احتجنا scheduled_task لاحقاً).
4. ميزات إضافية: استرجاع من report.json، معاينة Dry-run بالواجهة.
5. إصدار عام أول بعد التوقيع والتجربة.
