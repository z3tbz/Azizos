# Azizos — خطة المشروع (Engine + App)

> تطبيق واحد موقّع، يحل محل AME Wizard: المستخدم يفتحه → يفحص المتطلّبات → يختار التويكات → يطبّق بمتانة → ريستارت → يفتح AZIZ Gaming Optimizer.
> التويكات مخزّنة داخل التطبيق نفسه، ما فيه ملف `.apbx` يطلع للناس.

## 1. اللغة والبنية (مثبّتة)

- **المحرّك: Rust** — بايناري واحد، بدون runtime، آمن الذاكرة (أقل كراش من C++)، أداء شبه C++، لا يحتاج تحديثات مستقبلية.
- **الواجهة: Tauri** — عربي/إنجليزي، RTL للعربي، تبديل تلقائي على لغة الجهاز + يدوي.
- **التوافق:** ويندوز 10 و11، كل الإصدارات (Home/Pro/Enterprise/LTSC/IoT)، البيلدات 19044 → 26300.
- **كأدمن:** `requireAdministrator` في الـ manifest.
- **بدون درايفر kernel** (مثل البلاي بوك الحالي) → لا بلو سكرين من التطبيق.

## 2. تدفّق الشاشات

1. ترحيب + 3 نقاط تعريفية.
2. **فحص المتطلّبات (Pre-flight):** `DefenderToggled · NoAntivirus · PluggedIn`
   - (بدون متطلّب إنترنت — كل شيء مدمج داخل التطبيق، لا تنزيلات.)
   - كشف حالة كل متطلّب (قراءة فقط) → أخضر/أحمر.
   - معالجة: تلقائي (يشغّل سكربت المستخدم بموافقة) أو يدوي (فتح الصفحة المعنية داخل الواجهة) ثم إعادة فحص.
3. اختيار النمط (نمطان — خياراتهما لاحقاً) ثم تفصيل يدوي.
4. مراجعة + معاينة (Dry-run) تعرض بالضبط ما سيتغيّر.
5. التطبيق: بار تقدّم + سطر حالة + **Auto-Restart** (مفعّل افتراضياً) تحت على اليمين.
6. النهاية: تقرير + أرشيف ديسكتوب، ثم ريستارت → فتح الأوبتمايزر بعد الإقلاع (`RunOnce`).

## 3. قلب المحرّك: كله بيانات (declarative)

كل تويك كائن واحد (انظر `SCHEMA.md`) فيه:
- `id`, `name{ar,en}`, `description{ar,en}`, `category`, `profiles`, `default`
- `requires_reboot`
- `compat`: { builds min/max, editions, device, gpu, disk }
- `depends_on`, `conflicts_with`
- `actions[]`: registry | service | scheduled_task | appx | file | command | powershell | device | bcd | powerplan | env
- `verify[]`: كيف نتأكد إنه انطبّق فعلاً
- `revert`: تلقائي (snapshot للقيمة الأصلية) + تخصيص اختياري

**الفايدة:** بدل ~40 ملف `.bat`/`.reg` متناثرة، المحرّك يسوّي العمل عبر Windows API مباشرة → أسرع، أخف، أقل نقاط فشل، وإضافة/حذف تويك بدون لمس كود.

## 4. ذكاء التوافق (أقل تعارض مع ويندوز)

1. كشف النظام أول: build، edition، laptop/PC، GPU، SSD/HDD (يستبدل سكربتات الكشف المكررة).
2. بوابة توافق لكل تويك: ما ينطبّق إلا لو يخص هالنسخة/العتاد؛ غير المناسب **يُتخطّى** بدل ما يفشل.
3. محلّل تعارض: يرتّب التويكات (depends/conflicts) ويكشف أي تضارب قبل التنفيذ.

## 5. المتانة (ميزة AME + أفضل)

1. معاملات + نسخ احتياطي: snapshot قبل كل تويك → سجل تراجع على القرص + Restore Point تلقائي.
2. عزل الفشل: كل تويك لحاله؛ لو فشل يسجّل الكود + السبب ويكمّل، بدون توقّف/كراش.
3. فحص ما بعد التطبيق: يعيد قراءة كل تويك ويصنّفه (طُبّق / فشل / تُخطّي).
4. تقرير نهائي ثنائي اللغة (بشري + JSON) + أرشيف ديسكتوب.

## 6. الأداء

1. تنفيذ متوازي للتويكات المستقلة.
2. تخطّي المضبوط مسبقاً (idempotent) — تشغيل مرتين لا يخرّب شيئاً.
3. تجميع الحرج (requires_reboot) وتطبيقه أخيراً.

## 7. ميزات تتفوّق على AME

1. استكمال بعد الريستارت (Phased resume) على نظام حي.
2. وضع المعاينة (Dry-run) — شفافية كاملة قبل التطبيق.
3. حزمة استرجاع مستقلة (تصدير الحالة قبل التطبيق).
4. تثبيت برامج بتنزيل مباشر (بدل الاعتماد على choco).
5. فحص المتطلّبات التلقائي (القسم 2).
6. Auto-Restart + فتح الأوبتمايزر بعد الإقلاع.
7. نمطان (Profiles) مدعومان من الأساس.

## 8. التوافق والأمان

1. بايناري واحد **موقّع رقمياً** — أي نسخة محقونة ينكسر توقيعها.
2. فحص سلامة (hash) لبيانات التويكات قبل التطبيق.
3. البيانات مدمجة داخل البايناري، مو ملف منفصل.
4. محلي 100%، بدون تتبّع.

> صراحة: أي شيء يصل جهاز المستخدم يمكن تفكيكه نظرياً؛ التوقيع + كونه مجاني + رابط تحقّق رسمي يخلّون الانتحال **ينكشف ويصير غير مجدٍ** — أقوى من محاولة الإخفاء التام.

## 9. حالة البناء

- بيئة كلود الحالية سحابية بلا linker/شاشة → الكود يُكتب هنا، **البناء والتجربة على جهاز المستخدم**.
- خطوات البناء تُوثّق في `docs/BUILD.md`.

## 10. ترتيب العمل

1. ✅ الهيكل + Schema + أمثلة بيانات.
2. كشف النظام + فحص المتطلّبات (أول قطعة ملموسة للواجهة).
3. نواة المحرّك: تطبيق/تحقق/تراجع + idempotency + تعارض.
4. تنفيذ أنواع الـ actions عبر Windows API.
5. تحويل كامل تويكات البلاي بوك الحالي للـ Schema.
6. الواجهة (Tauri) + الربط.
7. التقرير + الأرشيف + الاسترجاع + RunOnce.
