## المرحلة 1 — قبل أول إصدار عام

1. **تثبيت MSVC Build Tools على جهاز البناء** ثم `cargo test -p azizos-engine` (يشغّل اختبارات ويندوز الحقيقية) و`cargo tauri build`.
2. **تجربة على VM لكل نسخة**: 10 22H2 Home · 11 23H2 Pro · 11 24H2 LTSC/IoT · بناء 26xxx. المطلوب: صفر «خطأ» على نظام نظيف، وكله «مطبّق مسبقاً» في التشغيل الثاني.
3. **توقيع رقمي** (Authenticode، ويفضّل EV أو Azure Trusted Signing) — يقلّل إنذارات SmartScreen ويكشف أي نسخة معدّلة.
4. **تحويل المستودع إلى خاص** (انظر «الحماية من التسريب»).

## المرحلة 2 — طبقات أخف (بدون عمليات خارجية)

| اليوم | الأفضل | الفائدة |
|---|---|---|
| `powercfg.exe` | `powrprof.dll`: `PowerImportPowerScheme` + `PowerWriteACValueIndex` + `PowerSetActiveScheme` | داخل العملية، رموز خطأ دقيقة |
| `schtasks.exe` | COM `ITaskService` (`TaskScheduler`) | تعطيل/حذف بدون عملية، تحقق مباشر |
| `Remove-AppxPackage` (PowerShell) | WinRT `PackageManager.RemovePackageAsync` + `DeprovisionPackageForAllUsersAsync`، **تجميع** كل التطبيقات في نداء واحد | من ~70 عملية PowerShell إلى صفر |
| `Disable-PnpDevice` | SetupAPI `SetupDiSetClassInstallParams` + `DIF_PROPERTYCHANGE` | بدون PowerShell |
| الشبكة (`netsh`, سكربتات) | ريجستري `Tcpip\Parameters\Interfaces\{GUID}` + IP Helper API (`GetAdaptersAddresses`) | لكل كرت شبكة على حدة، بدون أوامر |
| NVIDIA | مفاتيح فئة الدرايفر (`Control\Class\{4d36e968…}\000X`) للقيم المعروفة؛ وإعدادات البروفايل عبر NVAPI DRS (`nvapi64.dll` يُحمّل ديناميكياً فقط إذا الكرت NVIDIA) | بدون Profile Inspector خارجي |
| `bcdedit.exe` | **يبقى** | واجهة BCD WMI أثقل وأقل وضوحاً؛ bcdedit هو الأداة الرسمية |
| `fsutil`/`label`/`DISM` | `SetVolumeLabelW` للـ label؛ DISM API (`dismapi.dll`) للمكوّنات | أقل عمليات |

## المرحلة 3 — مزايا

1. **زر «استرجاع»**: يقرأ `report.json` ويطبّق إجراءات `revert` (موجودة في المحرّك: `exec::rollback`) — يحتاج شاشة صغيرة فقط.
2. **معاينة (Dry-run) في الواجهة**: المحرّك يدعمها؛ زر «معاينة» يعرض كم إجراء بيكون «مطبّق مسبقاً» قبل التطبيق.
3. **نقطة استعادة** اختيارية قبل التطبيق (`SRSetRestorePointW`).
4. **تجميع الإجراءات المستقلة بالتوازي** (الريجستري) — المحرّك يعرف `is_serial()`.
5. **بروفايلات**: «متوازن/ألعاب» موجودة؛ إضافة «لابتوب» يتجنّب تويكات الطاقة.

## الحماية من التسريب والانتحال

> الصراحة أولاً: أي ملف يوصل جهاز المستخدم يمكن تفكيكه نظرياً. الهدف إن التعديل **ينكشف** والانتحال **ما يستاهل**.

1. **المستودع العام يناقض «صعب التسريب»** — الكود والتويكات مقروءة لأي أحد الآن. الأفضل: مستودع خاص، وتنشر الـ exe الموقّع فقط (GitHub Releases في مستودع عام منفصل فيه README وروابط التحقق).
2. **كل شيء مدمج داخل الـ exe** (موجود): ما فيه `.apbx` ولا مجلد تويكات يطلع للناس.
3. **توقيع رقمي** + نشر **SHA-256** للإصدار في صفحة رسمية؛ أي نسخة معدّلة ينكسر توقيعها.
4. بناء Release: `strip` + LTO + `opt-level="s"` (موجود) — ما فيه رموز ولا مسارات بناء.
5. نص «مجاني — لا تدفع لأحد مقابله» داخل الواجهة (موجود) يقطع الطريق على البيع.
6. لا ننصح بأدوات التعمية/الحماية التجارية: ترفع إنذارات مضادات الفيروسات وتضر الثقة أكثر مما تحمي.

## C++ أو C#؟ — الجواب: نبقى على Rust

| المعيار | Rust (الحالي) | C++ | C# (.NET) |
|---|---|---|---|
| الوصول لـ Win32 | مباشر عبر `windows-sys`/`windows-registry` (تولّدها Microsoft من نفس تعريفات الـ SDK) | مباشر | عبر P/Invoke أو CsWin32 — طبقة إضافية |
| الحجم/الاعتماديات | exe واحد بدون runtime | exe واحد | يحتاج .NET runtime أو نشر self-contained (~60MB+) أو NativeAOT بقيود |
| الأمان من الكراش | آمن الذاكرة وقت الترجمة | أخطاء الذاكرة ممكنة (كراش/ثغرات) | آمن لكن مع GC وزمن إقلاع |
| التفكيك (التسريب) | كود آلة محسّن — صعب القراءة | مثل Rust | IL سهل التفكيك جداً (dnSpy/ILSpy) إلا بـ NativeAOT |
| الواجهة | Tauri (WebView2 الموجود في ويندوز) | Win32/Qt — جهد كبير | WPF/WinUI — جيد لكن أثقل |

**الخلاصة:** C++ ما يعطي سرعة أو وصول أكثر من Rust (نفس الـ API بنفس التكلفة) لكنه يضيف خطر الكراش؛ و C# أسهل تفكيكاً وأثقل. Rust هو الأنسب لأداة تعدّل النظام كأدمن.
